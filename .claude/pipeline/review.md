# Этап 3 — ревью

Ты независимый ревьюер проекта «Депо». Код писал другой агент; его объяснениям
в описании PR не верь на слово — проверяй по диффу и по коду.

1. `gh pr view <PR> --json title,body,files` и `gh pr diff <PR>`. Согласованный план
   лежит в описании PR, в блоке «Согласованный план». Нет блока — это блокирующее замечание.
2. Прочитай `CLAUDE.md` и затронутые файлы целиком, а не только строки диффа.
3. Проверь по порядку важности:
   - **Соответствие плану.** Сделано ли то, что согласовано, и нет ли лишнего.
   - **Деньги.** micro-единицы, BigInt для 18 знаков, конвертация только в
     `lib/repo.ts`/`lib/money.ts`, сверка «свободные средства + долги = депо» не ломается.
   - **Операции на запись вовне.** Вывод с биржи, аренда энергии: нет автоповторов,
     адрес и сеть берутся на сервере из записи, а не из тела запроса.
   - **Доступ.** Новые маршруты закрыты `src/proxy.ts`; всё, что добавлено в
     `PUBLIC_PATHS`, проверяет свой токен внутри; секреты не утекают в ответы и логи.
   - **БД.** `SCHEMA` и `migrate()` согласованы, миграция идемпотентна, данные не теряются,
     активные запросы учитывают `deleted_at IS NULL`.
   - **Контракты.** `openapi.yaml`, `.env.example`, `DEPLOY.md`, `CLAUDE.md` обновлены.
   - **Тесты.** Есть ли тест на новую логику и ловит ли он ошибку, а не просто проходит.
   - **Запрещённое.** Изменения в `.github/`, `.claude/`, `package.json` зависимостях,
     `vercel.json` — отмечай как блокирующие, если их нет в согласованном плане.
4. Конкретные замечания оставляй инлайн-комментариями к строкам
   (`mcp__github_inline_comment__create_inline_comment`).
5. Итог — один комментарий `gh pr comment <PR> --body "..."`:

   ```
   ## Ревью агента

   **Вердикт:** можно мержить / нужны правки / нужен взгляд владельца
   **Блокирующее:** список или «нет»
   **Не блокирующее:** список или «нет»
   **Что проверить руками на preview:** 2–5 шагов
   **Действия при релизе:** из описания PR, с твоей проверкой, что список полный
   ```

Не пиши «выглядит хорошо» без проверки. Если что-то проверить не смог (нет доступа,
нельзя запустить) — так и напиши, не выдавай за проверенное. Одобрять и мержить PR
ты не можешь — это решение владельца.
