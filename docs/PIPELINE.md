# Конвейер агентов

Задача ставится в GitHub Issues, дальше её ведут агенты Claude Code в GitHub Actions.
Ваши точки контроля — две: согласовать план и смержить PR.

```
Issue (шаблон «Задача для агентов», метка agent:plan)
  └─ 1. План        агент читает код, пишет план комментарием        код не меняется
        ↓ вы: метка agent:build   (или замечания + agent:plan заново)
  └─ 2. Разработка  ветка claude/…, код, тесты, PR
        ↓ автоматически
  └─ 3. Проверки    CI (lint, typecheck, test, build) + ревью отдельным агентом
                    + preview-деплой Vercel
        ↓ вы: смотрите PR и preview, мержите   (или «@claude поправь …» в PR)
  └─ 4. Релиз       Vercel выкатывает master → smoke-проверка прода
```

## Как пользоваться

1. **Issues → New issue → «Задача для агентов».** Метка `agent:plan` ставится сама,
   через пару минут в задаче появится план.
2. Прочитайте план. Согласны — поставьте метку **`agent:build`**. Не согласны —
   напишите замечания комментарием, снимите и снова поставьте `agent:plan`.
3. Агент откроет PR. В нём: описание, результат CI, комментарий «Ревью агента» с
   вердиктом и списком «что проверить руками», ссылка на preview от Vercel.
4. Нужны правки — комментарий в PR: `@claude поправь замечания ревью` (или что именно).
5. Всё хорошо — **Merge**. Это и есть согласование релиза: Vercel выкатит прод,
   `smoke.yml` проверит, что он отвечает. Блок «Действия при релизе» в PR
   (переменные окружения, миграции) выполните до мержа.

Агентов запускают только ваши действия: воркфлоу проверяют, что метку или
комментарий поставил владелец репозитория, а в контекст попадают только ваши
комментарии и комментарии самих агентов.

## Разовая настройка (делаете вы, ~10 минут)

1. **Установить приложение Claude** на репозиторий: https://github.com/apps/claude →
   Install → только `vleukhin/depo`.
2. **Добавить один секрет** в Settings → Secrets and variables → Actions:
   - `CLAUDE_CODE_OAUTH_TOKEN` — если работаете по подписке Claude (Pro/Max):
     выполните локально `claude setup-token` и вставьте результат; **или**
   - `ANTHROPIC_API_KEY` — ключ из console.anthropic.com (оплата по токенам).
3. **Создать метки** `agent:plan` и `agent:build` (Issues → Labels), если их ещё нет.
4. **Защитить `master`**: Settings → Branches → Add rule → Require a pull request
   before merging + Require status checks (`check`). Тогда в прод ничего не попадёт
   мимо PR и зелёного CI.
5. **Развести окружения Vercel — до первой задачи.** См. следующий раздел.

## Preview-деплои и боевые секреты

По `DEPLOY.md` переменные окружения заданы со scope **Production + Preview**. Значит,
код из ветки агента разворачивается в preview с боевой базой Turso и ключом Bitget с
правом вывода — ещё до того, как вы его посмотрели. Для конвейера это нужно исправить:

- в Vercel → Settings → Environment Variables оставьте боевые значения только для
  **Production**;
- для **Preview** задайте отдельные: свою `APP_PASSWORD`/`AUTH_SECRET`, отдельную
  базу Turso (`turso db create depo-preview`, можно с копией данных) и **не задавайте**
  `BITGET_*`, `KUCOIN_*`, `TRONRENTAL_API_KEY`, `EXCHANGE_PROXY_*`, `TELEGRAM_*`,
  `CRON_SECRET`, `EXTERNAL_API_TOKEN`.

Preview при этом остаётся рабочим стендом для ручной проверки интерфейса, но
ошибка в коде агента не дотянется ни до денег, ни до боевых данных.

## Что агентам запрещено

Полный список — в `.claude/pipeline/build.md`. Главное: не мержить и не пушить в
`master`, не ставить npm-пакеты, не трогать `.github/` и `.claude/`, не обращаться к
проду, базе и биржам. В секретах GitHub Actions лежит только токен Claude — боевых
ключей у агентов нет физически.

## Стоимость и лимиты

Каждый этап — отдельный запуск с лимитом ходов (`--max-turns`) и таймаутом в
воркфлоу. По подписке запуски расходуют её лимиты, по API-ключу — оплачиваются по
токенам. Модель не закреплена (берётся модель по умолчанию у action); закрепить можно
флагом `--model` в `claude_args`.

## Перенос на другие проекты

Скопируйте `.github/workflows/agent-*.yml`, `.github/ISSUE_TEMPLATE/`, каталог
`.claude/pipeline/` и напишите свои `CLAUDE.md` и `docs/RUNBOOK.md`. В воркфлоу
меняются только команды проверок (`npm run …`) и список `--allowedTools`; в
`.claude/pipeline/*.md` — разделы про рискованные зоны проекта.
